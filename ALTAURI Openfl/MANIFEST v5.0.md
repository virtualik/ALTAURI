## 2. Архитектурная Модель (Layered Cake)

Проект разделен на 4 независимых слоя. Взаимодействие осуществляется через **Data Binding**, **Priority Queue** и **Event Bus**.

### Слой 1: DRIVERS (Источники воздействия)

* **Роль:** Генерация данных извне и управление "активными" атомами.
* **Интеграция:** Базовый класс `Atom` реализует интерфейс `Driver`.
* **Компоненты:**`DriverManager`, `Driver` Interface, `MockSensorDriver`, `FPSDriver`.

### Слой 2: CORE / IO (Ядро логики)

* **Роль:** Чистая математика, трансформация данных и метаданные состояния.
* **Ключевые сущности:**
  * **`SignalQueue` (v2.0 Priority Scheduler):**
    * Реализует паттерн **Trampoline**.
    * **НОВОЕ:** Поддержка приоритетов (`enum Priority`).
      * `CRITICAL`: Ввод пользователя, системные события.
      * `NORMAL`: Основная логика вычислений (по умолчанию).
      * `BACKGROUND`: Визуализация, логирование.
    * **Load Shedding:** Метод `isOverloaded()` для реализации "ленивых" вычислений.
  * **`Blueprint` & `AtomDef`:**
    * **НОВОЕ:** В `AtomDef` добавлены опциональные поля `?x` и `?y` для хранения визуальных координат узлов внутри логической структуры данных. Это обеспечивает единый источник правды для Save/Load.
  * **`Contact`:**
    * *Link/Unlink API:* Единый механизм создания физических связей.
    * *Owner Reference:* Прямая ссылка на владельца (`Atom`) для оптимизации вызовов.
  * **`Atom`:**
    * *Hybrid Nature:* Реализует `IDisposable` и `Driver`.
    * *Zero-Allocation:* Кеширование входных данных (`_inputCache`).
  * **`Assembly`:**
    * *Safety:* Безопасная утилизация внутренних атомов с проверкой типов (`Std.isOfType`).

### Слой 3: EDITOR / ED (Визуализация)

* **Роль:** Инструмент управления графом.
* **Безопасность памяти (Memory Safety):**
  * **`NodeView`:** Реализован метод `dispose()`. Гарантирует отписку от событий `Contact` и удаление слушителей мыши.
* **Логика связей (Connection Logic):**
  * **`NodeEditor`:** Отказ от анонимных подписок (`subscribe`). Используется `Contact.link()`.
  * **НОВОЕ: State Restoration:** Метод `restoreExistingAtoms()`. При загрузке существующего `Blueprint` редактор автоматически проходит по списку атомов и создает для них визуальные представления (`NodeView`), восстанавливая координаты.
* **Интерфейс:**
  * **НОВОЕ:** Кнопка "Settings" (Гаечный ключ) на каждом узле. Отправляет импульс `ATOM_PROPERTIES_REQUEST`.

### Слой 4: DEVICE / GO (Интерфейс пользователя)

* **Роль:** Представление данных (HMI).
* **НОВОЕ: Properties Window:**
  * Всплывающее окно (`ui.PropertiesWindow`), вызываемое по клику на "гаечный ключ".
  * Динамически строит интерфейс на основе типа выбранного Атома.
  * Использует `NumberInput` и `NumberDisplay` для взаимодействия с `Contact`.
* **НОВОЕ: Clean Startup:** Приложение запускается с пустой сценой (Clean Slate). Пользователь сам создает структуру.

## 3. Протокол Взаимодействия (Interaction Protocol)

### Persistence (Save/Load)

* **Формат:** JSON (`.altauri`).
* **Сериализация:**`utils.ProjectIO`. Использует `openfl.net.FileReference` для доступа к файловой системе.
* **Процесс:**
  1. **Save:**`NodeEditor` собирает текущие координаты видов и обновляет поля `x`/`y` в `Blueprint.internalAtoms`. `ProjectIO` сериализует Blueprint.
  2. **Load:**`ProjectIO` парсит JSON -> создает новый `Assembly` -> `NodeEditor` пересоздается и вызывает `restoreExistingAtoms()`.

### UI Structure

* **Layers:**`Main` управляет слоями: `_editorLayer`, `_deviceLayer`, `_uiLayer`.
* **Switching:** Режимы Editor/Device переключаются видимостью слоев (`visible`), что сохраняет состояние DOM/отрисовки.

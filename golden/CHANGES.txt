ПОЛЕВАЯ ПРИЁМКА T-EMB (выполняется на Станции, после F5)
────────────────────────────────────────────────────────
  Команды — из папки bin/windows/bin (рядом с ALTAURI_Windows.exe).
  Golden-файлы скопировать туда же. Файлы golden_*.bin — ДАННЫЕ, не exe,
  не запускать (база фиктивная, помечена DO-NOT-EXECUTE).

  ── T-EMB.0 · сборка и нулевая регрессия ────────────────────────────
     F5 (или lime build cpp -static -clean). Редактор стартует как обычно.
     Двойной клик по exe = обычный редактор (хвост при старте ещё не
     читается — это Этап 2).

  ── T-EMB.1 · инспекция себя без хвоста ─────────────────────────────
       ALTAURI_Windows.exe --inspect
       echo %errorlevel%
     Ожидание: "tail: none", код 0.
     ЗАМЕТКА: если cmd вернул промпт мгновенно (GUI-подсистема не
     дожидается) — использовать:  start /wait ALTAURI_Windows.exe --inspect
     Вывод в любом случае попадает в консоль.

  ── T-EMB.2 · золотой мост Z-эталон ↔ Станция (главный тест) ───────
       ALTAURI_Windows.exe --inspect golden_altrpk1.bin > got.txt
       fc golden_altrpk1_inspect_expected.txt got.txt
       echo %errorlevel%
     Ожидание: различий НЕТ (fc молчит), код 0. Манифест — 4 записи:
     SCHEME, LIBRARY, ASSET и UNKNOWN(85) — проверка барьера
     совместимости. PowerShell-вариант сверки:
       Compare-Object (Get-Content golden_altrpk1_inspect_expected.txt) (Get-Content got.txt)
     (пустой вывод = совпадение).

  ── T-EMB.3 · золотая порча (CRC и версия) ──────────────────────────
       ALTAURI_Windows.exe --inspect golden_crc_fail.bin
       echo %errorlevel%      → ошибка CRC, код 3
       ALTAURI_Windows.exe --inspect golden_ver_fail.bin
       echo %errorlevel%      → "unsupported tail version 2", код 2
       ALTAURI_Windows.exe --inspect golden_plain.bin
       echo %errorlevel%      → "tail: none", код 0

  ── T-EMB.4 · сборка первого прибора ────────────────────────────────
       ALTAURI_Windows.exe --pack Device1.exe
     Ожидание: отчёт base/scheme/library/payload/output; Device1.exe
     рядом; размер = размер exe + payload + 24.
     (Схема берётся из Documents/ALTAURI/Selfrun.atom, библиотека — вся
     Library/*.atom. Сначала собери схему в редакторе!)

  ── T-EMB.5 · вскрытие прибора ──────────────────────────────────────
       ALTAURI_Windows.exe --inspect Device1.exe
     Ожидание: манифест с 1 SCHEME + N LIBRARY, все CRC OK, код 0.

  ── T-EMB.6 · анти-матрёшка ─────────────────────────────────────────
       ALTAURI_Windows.exe --pack Device2.exe --base Device1.exe
     Ожидание: "old tail truncated from base: yes"; инспекция Device2
     показывает base РАВНЫЙ base Device1 (не вложение!). При неизменной
     схеме размер Device2 == Device1.

  ── T-EMB.7 · guard'ы записи ────────────────────────────────────────
       ALTAURI_Windows.exe --pack ALTAURI_Windows.exe
     Ожидание: отказ "output path is the running executable", код 1.
     Редактор после этого жив-здоров (мы не трогали ни байта).

  ── T-EMB.8 · двойной клик по прибору ───────────────────────────────
     Device1.exe из проводника: стартует редактор как обычно. Хвост
     игнорируется при старте ДО Этапа 2 — это штатное поведение v1.

  ── T-EMB.9 (добровольно) · антивирусная разведка ───────────────────
     Проверить Device1.exe Защитником Windows. Реакцию (молчит /
     ругается на SFX-подобную структуру) зафиксировать в ответе —
     это данные риск-листа для эпохи [Export].

ОГРАНИЧЕНИЯ v1 (зафиксированы честно)
─────────────────────────────────────
  · CLI вывод ASCII-only — кириллица в cmd = cp866 кракозябры.
  · Сравнение путей в guard'ах строковое (Windows — без регистра);
    полный канонический разбор путей — эпоха Export-диалога.
  · Payload целиком читается в память; лимит читателя v1 — 1 ГБ.
  · На Linux остаточный риск guard'а при ОТНОСИТЕЛЬНЫХ путях (Станция —
    Windows; headless-эпоха перепроверит).
  · Вызов CLI — внутри Main.new(): lime успевает поднять скрытое окно
    (visible="false") до нашего выхода — для лабораторного инструмента
    допустимо; любые краши ловит чёрный ящик Trap.

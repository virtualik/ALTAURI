# 🌌 Altelius — Универсальная Среда Визуального Конструирования (УСВК)

> **Свет во тьме неисследованного космоса.**  
> **Зеркало, отражающее логику во всех направлениях реальности.**

Altelius — это **живая среда для проектирования поведения**.  
Она позволяет строить **работающие системы любой сложности** — от простых счётчиков до виртуальных устройств, логики IoT и реактивных алгоритмов — **без написания кода вручную**.

Вместо строк — **атомы**.  
Вместо компилятора — **связи**.  
Вместо ошибок — **чистая, неизменяемая архитектура**.

---

## 🔬 Суть проекта

Altelius реализует **Универсальную Среду Визуального Конструирования (УСВК)** — платформу, где:

- **Атом** — базовый строительный блок: компонент с входами, выходами и внутренней логикой.
- **Пин** — контакт для передачи данных или импульсов.
- **Трек** — соединение между пинами, через которое течёт поведение.
- **Схема** — сеть атомов, описывающая полную логику устройства или программы.

> Цель: **Дать каждому возможность конструировать сложные системы так же, как ребёнок собирает конструктор.**

---

## 🧩 Ключевые принципы

### ✅ Атомарность
Каждый атом — **независимая, переиспользуемая сущность** с чётко определённым поведением.  
Атомы могут быть:
- **Источниками** (кнопка, сенсор),
- **Логикой** (счётчик, элемент И),
- **Выходами** (дисплей, актуатор).

### ✅ Визуальное программирование
Логика строится **визуально** на холсте (`EditorWindow`) путём соединения пинов треками.  
Никакого синтаксиса. Никакой компиляции. Только **поток поведения**.

### ✅ Двойной режим работы
- **`EditorWindow`** — среда проектирования и отладки схем.
- **`DeviceWindow`** — чистое исполнение готовой схемы, как виртуального устройства.

### ✅ Открытая экосистема
Любая внешняя система — железо (через ANE), библиотека на C++, веб-API — может быть **интегрирована как атом**.  
Altelius — это **универсальный адаптер реальности**.

## 🏗️ Многокурсовая архитектура

### 🧭 Altelius построен как **многокурсовая платформа** — набор автономных, но взаимодействующих модулей («курсов»), каждый из которых отвечает за свою предметную область.

💡 Термин «курс» (от англ. course — направление, поток) означает автономный модуль системы, отвечающий за свою предметную область и запускаемый в строгой последовательности.

| Курс | Назначение |
|------|------------|
| **Core** | Ядро: команды, жизненный цикл, управление потоком инициализации |
| **MultiPulsator** | Нервная система: асинхронная коммуникация через импульсы (паттерн Publisher-Subscriber) |
| **Windows** | Управление окнами: `EditorWindow`, `DeviceWindow`, `ConsoleWindow` |
| **Stage3D** | 3D-визуализация и рендеринг (в разработке) |
| **AssetDispatcher** | Контролируемая загрузка ресурсов (изображения, звуки, модели) |
| **AtomLinker** | Сердце УСВК: создание, связывание и исполнение атомов |

### 🔑 Архитектурные принципы:
- **Полная изоляция курсов**: каждый курс независим от внутренностей других.
- **Единая коммуникация**: все взаимодействия через `MultiPulsator`.
- **Единое состояние**: `DataManager` — централизованное хранилище данных приложения.
- **Команды как интерфейс**: любое действие — объект `Command`, позволяющий строить сложные последовательности и откатывать операции.

---

## ⚛️ Неизменяемая реактивная модель

Altelius основан на **неизменяемой архитектуре**:

- **`BaseAtom`** — неизменяемая модель атома. Любое изменение создаёт **новую версию**.
- **`Pin`** — неизменяемый контакт. Его значение обновляется созданием нового пина.
- **`Реактивность`**: при изменении выхода атома → автоматически обновляются все подключённые входы → вызывается логика атомов-приёмников.

Это гарантирует:
- Отсутствие побочных эффектов,
- Простоту отладки,
- Возможность отката состояния,
- Безопасность в асинхронной среде.

## 📜 AtomICScript — декларативный язык поведения

Вместо захардкоженной логики, Altelius использует **AtomICScript** — **декларативный DSL для описания поведения атомов**.

AtomICScript построен на трёх столпах:

### 🔤 Типы пинов
```
"bool"   // истина/ложь (импульсы, кнопки)
"int"    // целые числа (счётчики, сенсоры)
"float"  // числа с плавающей точкой
"signal" // временный импульс
"any"    // универсальный тип
```

### ⚡ Триггеры поведения
```
"on_change"     // при любом изменении
"on_true"       // только при переходе в true
"on_false"      // только при переходе в false
"on_rising"     // аналог on_true
"on_falling"    // аналог on_false
"on_value"      // при любом значении (для чисел)
```

### 🛠 Встроенные действия
```
"increment('pin')"        // out += 1
"decrement('pin')"        // out -= 1
"set('pin', value)"       // out = value
"toggle('pin')"           // out = !out
"pass('in', 'out')"       // out = in (буфер)
"pulse('pin', duration)"  // отправить импульс на N мс
"reset('pin')"            // сброс к начальному
```

### 🧪 Примеры атомов в AtomScript

#### 🔘 Кнопка
```json
{
  "atom": "Button",
  "inputs": [],
  "outputs": [{ "name": "out", "type": "bool", "initial": false }],
  "behavior": {
    "on": "external_event",
    "event_type": "click",
    "do": "set('out', true); delay(50ms); set('out', false)"
  }
}
```
💡 `click` — это специальное внешнее событие, генерируемое ButtonAtomView, а не входной пин.

#### 🔢 Счётчик
```json
{
  "atom": "Counter",
  "inputs": [{ "name": "in", "type": "bool" }],
  "outputs": [{ "name": "out", "type": "int", "initial": 0 }],
  "behavior": {
    "on": "in",
    "trigger": "on_true",
    "do": "increment('out')"
  }
}
```

#### 🖥️ Числовой дисплей
```json
{
  "atom": "NumberDisplay",
  "inputs": [{ "name": "in", "type": "any" }],
  "outputs": [],
  "behavior": {
    "on": "in",
    "do": "display('in')"
  }
}
```
💡 `display` — специальное действие для UI.

#### ⚡ Логика И
```json
{
  "atom": "AndGate",
  "inputs": [
    { "name": "a", "type": "bool" },
    { "name": "b", "type": "bool" }
  ],
  "outputs": [{ "name": "out", "type": "bool", "initial": false }],
  "behavior": {
    "on": ["a", "b"],
    "do": "set('out', pin('a') && pin('b'))"
  }
}
```

### 💡 Преимущества этого подхода

- **Новые атомы без кода** — просто опишите в JSON/YAML.
- **Визуальный редактор поведения** — можно построить UI-конструктор на основе DSL.
- **Тестирование** — поведение можно симулировать вне UI.
- **Сериализация** — схемы можно сохранять/загружать как JSON.
- **Метапрограммирование** — генерация атомов «на лету».

Это позволяет:

- Создавать новые типы атомов без написания кода,
- Экспортировать/импортировать схемы как JSON,
- Строить визуальные редакторы поведения,
- Интегрироваться с внешними системами (например, Matter, MQTT, HTTP).

## 🧠 AtomVM — суверенный цифровой организм

### Что такое AtomVM в контексте системы?

AtomVM — это не просто «виртуальная машина».  
**Это суверенный цифровой организм, способный создавать, исполнять и эволюционировать поведение независимо от внешнего мира.**

*«Атом — это чистая функция, которая преобразует входные сигналы в выходные через внутреннее состояние, соединённые в граф для создания сложного поведения.»*  
— ViRTUALiK

Это движок исполнения схем, где:

- **Атом (Elemental)** = инструкция,
- **Связь (Track)** = поток данных,
- **Импульс (PIN_UPDATED)** = сигнал исполнения,
- **AtomICScript (Alpfabet)** = байт-код поведения,
- **AtomManager (BrainBank)** = регистровая память,
- **ConnectionManager (NerveStream)** = шина данных.

Это **машина потоков данных**, но с неизменяемым состоянием, чистыми функциями поведения и реактивной передачей управления.

### Уже реализованное ядро AtomVM:
- **BaseAtom** — регистр состояния
- **Pin** — порт ввода-вывода
- **Track** — канал передачи данных
- **AtomICScriptManager** — интерпретатор поведения
- **ConnectionManager** — планировщик исполнения
- **MultiPulsator** — системная шина событий

**Это уже работает** — просто пока в оболочке визуального редактора.

### Следующие шаги к суверенности:

1. **Изолировать AtomVM от UI**
   - Перенести исполнение схем в отдельный модуль `Application/AtomVM/`
   - `EditorWindow` и `DeviceWindow` станут фронтендами к одной машине

2. **Добавить поддержку временных примитивов**
   - `delay`, `debounce`, `sequence` как расширения `IAtomBehavior`

3. **Ввести «глобальные события» как входы схемы**
   - Кнопка → `external_event("click")` → AtomVM → реакция

4. **Экспортировать схему как «программу»**
   - JSON-описание атомов + связи + AtomICScript = полный образ поведения

5. **Запускать схему в headless-режиме**
   - Без окон, без рендера — только логика, только поведение

## 🌐 AtomOS: единая операционная система для IoT

**AtomOS** — это новая парадигма в мире интернета вещей (IoT).  
Она объединяет все устройства, от любого производителя, использующие любой протокол, в одну универсальную, реактивную, визуально программируемую систему.

### 🔧 Компоненты AtomOS

AtomOS состоит из трёх ключевых компонентов, работающих вместе:

1. **AtomLinker** — среда визуального программирования
2. **AtomICScript** — универсальный язык поведения
3. **AtomVM** — среда исполнения (виртуальная машина) для AtomOS

### 1. 🧩 AtomLinker — визуальный мозг

AtomLinker — это редактор, где пользователи строят схемы, соединяя атомы.

- **Атом** — базовая единица поведения (кнопка, счётчик, дисплей, сенсор, реле)
- **Пин** — вход/выход атома (bool, int, float, signal, any)
- **Трек** — связь между пинами, где «течёт» поведение
- **Схема** — граф атомов, описывающий полное поведение устройства или системы

**Преимущества:**
- **Без кода**: поведение строится визуально
- **Модульность**: атомы — переиспользуемые блоки
- **Наглядность**: логика в виде связей

### 2. 🧠 AtomICScript — душа схем

AtomICScript — это не «язык программирования» в традиционном смысле.  
Это интерфейс поведения (`IAtomBehavior`) и его реализации.

- **IAtomBehavior** — шаблон для описания реакции атома на изменение входного пина
- **onInputPinChanged(atom, changedPin)** — универсальный «слот» для конкретной логики
- **Behavior** — чистая функция: `f(old_atom, changed_pin) → new_atom`

**Пример (из AS3):**
```actionscript
// Application/AtomICScript/IAtomBehavior.as
public interface IAtomBehavior {
    function onInputPinChanged(atom:BaseAtom, changedPin:Pin):BaseAtom;
}

// Application/AtomICScript/behaviors/CounterAtomBehavior.as
public class CounterAtomBehavior implements IAtomBehavior {
    public function onInputPinChanged(atom:BaseAtom, changedPin:Pin):BaseAtom {
        if (changedPin.value === true) {
            var currentValue:int = atom.getOutputPinValue("out") as int || 0;
            return atom.setOutputPinValue("out", currentValue + 1);
        }
        return atom; // Без изменений
    }
}
```

**Преимущества:**
- **Модульность**: каждый тип атома имеет своё поведение
- **Портируемость**: поведение независимо от UI или VM
- **Простота**: логика в виде «чистых функций»

### 3. ⚙️ AtomVM — сердце AtomOS

AtomVM — это среда исполнения, которая:

- Загружает схемы (например, JSON)
- Создаёт атомы и их связи
- Исполняет поведение атомов (AtomICScript)
- Интегрируется с внешними устройствами (Zigbee, HTTP, GPIO и т.д.)

**Реализация на C (гипотетический пример):**
```c
// atom_vm.h
typedef struct {
    int id;
    int type;
    int input_count;
    int output_count;
    int *input_values;
    int *output_values;
} atom_t;

typedef struct {
    atom_t* (*react)(atom_t* atom, int changed_pin_idx, int new_value);
} atom_behavior_t;

// device_integration.c
typedef struct {
    const char* protocol;  // "zigbee", "zwave", "http"
    void* protocol_data;   // специфичные для протокола данные
    atom_t* atom;          // атомарное представление
} device_driver_t;

// atom_vm_core.c
void atomvm_register_device(device_driver_t* driver) {
    // Транслировать протокол в атомарный интерфейс
    atom_t* unified_atom = translate_protocol_to_atom(driver);
    // Добавить в глобальный граф
    graph_add_atom(global_graph, unified_atom);
    // Подписаться на изменения
    subscribe_to_device_events(driver, on_device_event);
}

void on_device_event(device_driver_t* driver, const char* event, void* value) {
    // Обновить атомарное представление
    atom_set_pin_value(driver->atom, event, value);
    // Запустить вычисления графа
    atomvm_execute_cycle(global_graph);
}
```

**Преимущества:**
- **Портируемость**: может быть скомпилирован для любой платформы (C, Rust, Zig)
- **Минимализм**: маленький размер, максимальная производительность
- **Универсальность**: интеграция с любыми протоколами через «драйверы»
- **Реактивность**: изменение одного пина — цепь реакций

### AtomOS как «шлюз к мостам»

- **Физические устройства** (сенсоры, реле, лампы) становятся `atom_t` внутри AtomVM через `device_driver_t`
- **AtomVM** — это «шлюз», «мозг», «мост» между реальным миром и логикой схем
- **AtomICScript** — это «дух действий», управляющий всеми атомами
- **AtomLinker** — это «IDE», где этот «мозг» создаётся

## 📐 Математическая формализация

### Универсальная формула
```
AtomVM: System = ⟨Atoms, Tracks, Impulses, Behaviors, Managers⟩

∀ atom ∈ System:
  When Δpin ∈ atom.inputs:
    atom' = Behavior[atom.type](atom, Δpin)

Где:
  atom' — новый экземпляр атома
  Behavior — чистая функция преобразования
  Δpin — изменённый входной пин
```

### Минималистская модель
```
AtomICScript ::= (Atom × PinΔ) → Atom'

Где:
  Atom = ⟨id, type, inputs, outputs, state⟩
  PinΔ = ⟨name, newValue⟩
  Atom' = новый экземпляр Atom
```

### Интерфейс
```typescript
interface ReactiveBehavior {
    react(atom: Atom, changedPin: Pin): Atom;
}
```

### Принцип
«Каждое изменение входа порождает новое состояние атома»

### Свойства
- **Чистота**: нет побочных эффектов
- **Идемпотентность**: повтор = тот же результат
- **Композируемость**: атомы соединяются в графы
- **Изоляция**: поведения независимы

### Финальная формулировка
«AtomICScript — это интерфейс реактивного программирования, где атомы представляют чистые функции, преобразующие изменения входов в новые состояния, а графы атомов формируют композицию этих функций.»

Эта модель идеально подходит для:
- Функционального программирования
- Реактивных систем
- Неизменяемых структур данных
- Распределённых вычислений

## 🔧 Архитектурные принципы

1. **Неизменяемость**: атомы не меняются, создаются новые
2. **Реактивность**: изменение → импульс (PIN_UPDATED) → цепь реакций
3. **Модульность**: атомы, поведения, драйверы независимы
4. **Портируемость**: схема и поведение не зависят от платформы

## 💡 Пример использования

1. Пользователь создаёт схему в AtomLinker: `ZigbeeMotionSensor → ANDGate → WiFiLightController`
2. Схема экспортируется в JSON
3. JSON и AtomVM загружаются на роутер с OpenWRT
4. AtomVM запускается, создаёт атомы, подписывается на адаптер Zigbee
5. При срабатывании сенсора → AtomVM исполняет цепь → свет включается

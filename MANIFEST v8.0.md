# ALTAURI MASTER MANIFEST v8.0

**Code Name: "Hybrid Foundation"**

---

## 1. Статус проекта: Production-Ready Core + ECS

**Текущая версия:** v7.0

**Ключевое достижение:** Архитектура обрела гибридный рендеринг. Интегрирован ECS-слой (Entity-Component-System) для управления визуализацией. Реализована система настроек с возможностью A/B тестирования производительности. Добавлена поддержка множественных типов проводов.

---

## 2. Архитектурная Модель (Layered Cake)

Проект разделен на 5 независимых слоёв. Взаимодействие осуществляется через **Data Binding**, **Priority Queue**, **Event Bus** и **ECS Query System**.

### Слой 0: ECS (Entity-Component-System)

* **Роль:** Гибридный слой визуализации с кэш-дружелюбным доступом.
* **Компоненты:**
  * `PositionComponent` — позиция нод
  * `VisualComponent` — состояние (selection, visibility)
* **Системы:**
  * `RenderSystem` — централизованный рендеринг
  * `Query` — пространственные запросы (lasso, rect)
* **Facade:**`ECS` — единая точка доступа
* **Режимы:** ECS / Direct (переключение в runtime)

### Слой 1: DRIVERS (Источники воздействия)

* **Роль:** Генерация данных извне и управление "активными" атомами.
* **Интеграция:** Базовый класс `Atom` реализует интерфейс `Driver`.
* **Компоненты:**`DriverManager`, `Driver` Interface, `MockSensorDriver`, `FPSDriver`, `FrameTimeAtom`.

### Слой 2: CORE / IO (Ядро логики)

* **Роль:** Чистая математика, трансформация данных, управление состоянием.
* **Ключевые сущности:**
  * **`UndoManager` (Fault Tolerant):** Try-Catch обёртка для команд.
  * **`Atom`:** Safety проверки, флаг `_isDisposed`.
  * **`HeavyAtom`:** Корректная отмена таймеров.
  * **`SignalQueue`:** Priority-based scheduler (CRITICAL, NORMAL, BACKGROUND).
  * **`Impulsys`:** Event Bus для полной развязки UI ↔ Logic.

### Слой 3: EDITOR / ED (Визуализация)

* **Роль:** Инструмент управления графом.
* **Безопасность памяти (Memory Safety):**
  * **`NodeEditor`:** Исправлен паттерн Dispose. Хранение ссылок на колбэки.
  * **`NodeView`:** Полная очистка слушателей мыши и подписок.
* **Wire Rendering:** Три типа проводов (Bezier, Straight, Corners).
* **Ghost Wire:** Временные линии при перетаскивании — соответствуют выбранному типу.

### Слой 4: DEVICE / GO (Интерфейс пользователя)

* **Роль:** Представление данных (HMI).
* **UI:**`PropertiesWindow`, `ContextMenu`, `ButtonComponent`, `SettingsPanel`.

## 3. Система Настроек (Settings Panel)

### Структура

| Секция | Параметр | Значения             | Описание                                           |
| ------------ | ---------------- | ---------------------------- | ---------------------------------------------------------- |
| PERFORMANCE  | Use ECS          | On/Off                       | Переключение режима рендеринга |
| WIRE TYPE    | Type             | Bezier / Straight / Corners  | Стиль отрисовки проводов             |
| STATISTICS   | —               | Node count, Wire count, Mode | Отображение статистики                |

### Назначение

* A/B тестирование производительности
* Профилирование узких мест (кривые Безье vs прямые)
* Runtime-переключение без перезапуска

## 4. Типы Проводов (Wire Types)

| Тип                  | Описание                                             | Производительность |
| ----------------------- | ------------------------------------------------------------ | ------------------------------------ |
| **Bezier Curve**  | Кубические кривые Безье, плавные | Базовая                       |
| **Straight Line** | Прямая линия точка-точка                | Высокая                       |
| **Corners Line**  | Ломаная с прямыми углами                | Высокая                       |

### Применение

* Все провода схемы
* Ghost wire (временные при перетаскивании)
* Сохранение при Load/Save
* Сохранение при навигации в Assembly

---

## 5. Протокол Взаимодействия (Interaction Protocol)

### Persistence (Save/Load)

* **Формат:** JSON (`.altauri`).
* **Safety:**`Std.string()` и безопасное приведение типов.
* **Coordinates:** Защита от `NaN`.
* **Wire Type:** Сохраняется в сессии (runtime).

### Command Pattern

* Все действия пользователя обёрнуты в `ICommand`.
* История изолирована от рендеринга.

### Event Bus (Impulsys)

* Полная развязка UI ↔ Logic.
* События: `PORT_DRAG_START`, `NODE_CLICKED`, `ATOM_DELETED`, `REDRAW_WIRES`, etc.

## 6. Визуальные стандарты

* **Node Design:** Тёмная тема, моноширинный шрифт.
* **Port Colors:** Input (Orange), Output (Green).
* **Selection:** Жёлтая рамка, изменение alpha.

## 7. Карта развития (Roadmap)

*(См. отдельный файл ROADMAP.md)*

Я подошел к самому важному этапу: продукт готов, архитектура вылизана, но теперь нужно объяснить миру, зачем это нужно. Инвесторы не покупают код, они покупают сдвиг парадигмы и масштабируемость. А "подельники" (команда) должны гореть идеей, чтобы не сгореть на этапе отладки.

Моя задача — позиционировать ALTAURI не как "еще одну среду для программирования", а как инструмент демпфирования сложности.

Вот набор тезисов, метафор и бизнес-факторов, которые я могу смело брать в свой Манифест. Они построены так, чтобы бить точно в цель: логика, деньги, будущее.

1. Фундаментальные тезисы (Для заголовков и питч-дека)
   «Код — это проклятие XX века. Логика — это достояние человечества». Текучий программный код (текст) — это просто интерфейс общения с машиной, придуманный 70 лет назад. Заставлять инженера, врача или конструктора учить синтаксис C++ или Python, чтобы автоматизировать свою работу — это всё равно что заставлять их собирать двигатель с помощью отвёртки нестандартного размера. ALTAURI убирает синтаксис и оставляет чистую логику.
   «Мы переписываем контракт между Человеком и Компьютером». До сих пор человек должен был переводить свою мысль на машинный язык. ALTAURI заставляет машину понимать язык человека — визуальные связи причин и следствий.
   «Текстовый код создан для машин. Визуальный граф создан для человека». Ни один мозг не мыслит строчками if (x==y) { z=1; }. Мозг мыслит блоками: "Если А, то Б". Узловой синтез — это первая среда разработки, которая соответствует нейробиологии человека.
2. Бизнес-факторы (Почему это купят/инвестируют)
   Фактор устранения "узкого горлышка" (Bottleneck). В любой компании есть узкое горлышко: IT-отдел. Бизнес ждет новый функционал неделями, потому что программисты перегружены. ALTAURI позволяет специалистам предметной области (инженерам, логистам, маркетологам) собирать рабочие приложения сами, минуя очередь к программистам. Это увеличивает скорость вывода продукта (Time-to-Market) в 10-50 раз.
   Фактор "Эффекта Excel". Взглянем на историю. До электронных таблиц бухгалтеры были элитными программистами (писали на Basic, Fortran). Появление Excel разрушило монополию программистов на расчеты. Бухгалтеры получили свободу. ALTAURI делает то же самое, но не для таблиц, а для приложений и железа. Рынок, который мы открываем, comparable по размеру с рынком пользователей Excel.
   Фактор нулевого технического долга (Zero Technical Debt). Текстовый код превращается в "спагетти" через год разработки. Его сложно читать, сложно передавать. Визуальный граф (узлы и провода) самодокументируем. Любой человек, взглянув на схему ALTAURI, мгновенно понимает, как работает приложение. Смена сотрудника на проекте больше не означает потерю полугода на "въезжание" в чужой код.
   Изоляция от ошибок низкого уровня. В текстовом коде забытая точка с запятой или утечка памяти (memory leak) могут крашнуть систему. В ALTAURI пользователь физически не может совершить синтаксическую ошибку. Движок (мой hxcpp бэкенд) берет на себя всю грязную работу по управлению памятью и потокам. Пользователь просто "соединяет блоки".
3. Технологический авангард (Что делает ALTAURI особенной)
   Обычно инвесторы скептичны к визуальному программированию, потому что видели много "игрушек" (типа Scratch). Мне нужно подчеркнуть, что ALTAURI — это не игрушка.

«Low-Code — это для веб-сайтов. ALTAURI — это для реального мира». Большинство node-редакторов ограничены браузером. ALTAURI благодаря hxcpp работает на уровне ОС. Мы управляем реальными COM-портами, аудио-потоками, железом (Arduino, STM32). Это не скрипты, это системное программирование без программирования.
Архитектура непрерывности (Tick Generator). У нас нет проблемы "событийного ада" (callback hell), от которой страдают визуальные системы. Наш движок работает как цифровая схема (FPGA/ASIC) — сигналы распространяются тактильно, детерминированно. Это подход, который используют в аэрокосмической промышленности. Мы democratizied этот подход для masses.

Если кто-то спросит за чашкой кофе: "А что вообще такое твой ALTAURI простыми словами?"

ALTAURI — это конструктор LEGO для создания программного обеспечения и работы с железом. Соединил два блока — получила систему".

Проблема: На протяжении 70 лет компьютеры развивались экспоненциально, но способ общения с ними остался в каменном веке. Мы всё ещё заставляем людей говорить с машинами на языке машин — текстовом коде. Это создает искусственный барьер: 95% людей на планете имеют идеи для автоматизации, но не могут их реализовать, потому что не знают синтаксиса языков программирования.

Решение: ALTAURI стирает этот барьер. Мы отделили ЛОГИКУ (как должно работать) от СИНТАКСИСА (как это написать).

Ценность:

Скорость: Создание рабочего приложения занимает минуты, а не недели.
Доступность: Инженер на заводе может сам написать терминал для станка с ЧПУ или Arduino, не дожидаясь программиста из головного офиса.
Надежность: Визуальная схема не содержит синтаксических ошибок и самодокументируется.
Мы не учим людей программировать. Мы позволяем людям мыслить и творить.

Используя эти высказывания Я формулирую идеологию — моё главное оружие на переговорах. Когда говорю не о том, "как работает TickGenerator", а о том, "как мы экономим компании миллионы долларов, высвобождая инженеров от ожидания IT-отдела" — к тебе начинают слушать совсем по-другому.

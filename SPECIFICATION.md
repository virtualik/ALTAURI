# Техническое Описание Системы ALTAURI

## Классификация по Секторам Ответственности

---

## Тезис о Вычислительном Ядре

**Подтверждаю и дополняю.**

Система ALTAURI является **Реактивной Системой Потоковой Калькуляции**. Её "сердце" — не просто вычислительное ядро, а **Планировщик Сигналов (SignalQueue)**, который:

1. **Не вычисляет сам** — он *планирует* вычисления
2. **Устраняет рекурсию** — превращает каскадные вызовы в итеративную очередь
3. **Гарантирует завершение** — защита от бесконечных циклов через лимит итераций

Это важное различие: Ядро не *считает*, Ядро *организует* счёт.

## Структура Ответственности

### 🜄 ЯДРО (Core)

*Базовый уровень. Не зависит от UI. Чистая логика.*

| Сущность      | Ответственность                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Atom**        | Единица вычисления. Хранит функцию трансформации. Реагирует на изменение входов. |
| **Contact**     | Точка передачи данных. Хранит значение. Уведомляет подписчиков. Связывает Атомы.  |
| **Assembly**    | Композитный Атом. Инкапсулирует подграф. Пробрасывает сигналы через ConductorPort.         |
| **Blueprint**   | Паспорт Атома. Описание структуры без логики выполнения. Сериализуем.                      |
| **SignalQueue** | Диспетчер задач. Планирует вычисления по приоритетам. Защищает от переполнения.   |
| **Impulsys**    | Шина событий. Децентрализованная коммуникация между подсистемами.                           |

---

### 🜃 БИБЛИОТЕКА (Library)

*Расширяемость. Регистрация типов. Специализированные атомы.*

| Сущность          | Ответственность                                                                                              |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **AtomRegistry**    | Каталог типов. Связывает ID → Blueprint. Загружает внешние определения.    |
| **AssemblyFactory** | Фабрика экземпляров. Создаёт Atom или Assembly по Blueprint.                                  |
| **Active Atoms**    | Атомы с собственным жизненным циклом (FPSMonitor, FrameTime). Требуют DriverManager. |

---

### 🜂 РЕДАКТОР (Editor)

*Визуальное манипулирование графом. Интерактивность.*

| Сущность     | Ответственность                                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NodeEditor** | Координатор сцены. Управляет видами узлов, проводами, навигацией. Обрабатывает жесты. |
| **NodeView**   | Представление узла. Отрисовка, порты, перетаскивание, выбор.                                                |
| **WireLayer**  | Слой связей. Отрисовка кривых Безье. Визуализация потока.                                                     |

---

### 🜁 КОМАНДНАЯ СИСТЕМА (Commands)

*История действий. Отмена/Повтор. Транзакции.*

| Сущность            | Ответственность                                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **UndoManager**       | Хранитель истории. Управляет стеками Undo/Redo. Ограничивает глубину. |
| **Command**           | Атомарное действие. Знает как выполнить и как отменить.                    |
| **MacroCommand**      | Группа действий. Атомарная транзакция из нескольких команд.           |
| **ConnectCommand**    | Создаёт/разрывает связь между контактами.                                            |
| **CreateAtomCommand** | Создаёт/удаляет экземпляр атома.                                                             |
| **DeleteAtomCommand** | Удаляет/восстанавливает атом со связями.                                              |
| **MoveNodeCommand**   | Перемещает узел. Обновляет координаты в Blueprint.                                     |
| **GroupAtomsCommand** | Преобразует выборку в новую Assembly. Регистрирует в библиотеке.          |

---

### ⏣ СИСТЕМА ДАННЫХ (Persistence)

*Сохранение. Загрузка. Сериализация.*

| Сущность     | Ответственность                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **ProjectIO**  | Файловые операции. Диалоги сохранения/загрузки. Восстановление состояния. |
| **Serializer** | Преобразование Blueprint ↔ JSON. Нормализация типов.                                                      |

---

### ⏥ UI СИСТЕМА (User Interface)

*Взаимодействие с пользователем. Отображение состояния.*

| Сущность           | Ответственность                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **DevicePanel**      | Режим устройства. Отображение Input/Output виджетов. Runtime-взаимодействие. |
| **PropertiesWindow** | Редактор свойств атома. Ввод/вывод значений в реальном времени.         |
| **ContextMenu**      | Контекстное меню. Быстрый доступ к действиям.                                          |
| **SkinManager**      | Визуальные стили. Цвета, размеры, формы по категориям.                           |
| **Widgets**          | HMI-элементы (NumberInput, NumberDisplay). Связь Contact ↔ Пользователь.                           |

---

### ⏧ МЕНЕДЖЕРЫ (Managers)

*Жизненный цикл. Глобальное состояние.*

| Сущность        | Ответственность                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **DriverManager** | Управление активными атомами. Вызов update() каждый кадр. Точный Δt. |
| **Registry**      | Глобальный каталог экземпляров. (Потенциально — поиск по ID).        |
| **UndoManager**   | (см. Командная Система)                                                                            |

## Ключевое Наблюдение

Система ALTAURI — это **два параллельных мира**:

1. **Модель (Core)** — граф атомов, контактов, связей. Живёт в памяти. Обрабатывает данные.
2. **Представление (Editor/UI)** — граф видов, портов, проводов. Отображает модель. Принимает жесты.

**Связь между мирами** осуществляется через:

* **Impulsys** — событийная шина (Model → View)
* **Commands** — действия пользователя (View → Model)

Это разделение — **фундаментальное архитектурное решение**, обеспечивающее:

* Независимость ядра от платформы
* Возможность нескольких представлений (Editor, Device, VirtualDevice)
* Тестируемость логики без UI

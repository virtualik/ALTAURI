# ALTAURI MASTER MANIFEST v5.0

**Code Name: "Hardened Core"**

---

## 1. Статус проекта: Hardened Production Core

**Текущая версия:** v5.0**Ключевое достижение:** Архитектура прошла фазу "Technical Debt Repayment". Внедрена система приоритетов выполнения, устранены утечки памяти (GC Leaks), реализована безопасность типов при очистке ресурсов. Ядро готово к промышленной нагрузке и расширению библиотеки активных компонентов.

---

## 2. Архитектурная Модель (Layered Cake)

Проект разделен на 4 независимых слоя. Взаимодействие осуществляется через **Data Binding** и **Priority Queue**.

### Слой 1: DRIVERS (Источники воздействия)

* **Роль:** Генерация данных извне и управление "активными" атомами.
* **Интеграция:** Базовый класс `Atom` теперь реализует интерфейс `Driver`, что позволяет создавать "Самостоятельные Атомы" (Self-contained Atoms), способные регистрировать себя в системе и тикать каждый кадр без внешних "костылей".
* **Компоненты:**`DriverManager`, `Driver` Interface, `MockSensorDriver`, `FPSDriver`.

### Слой 2: CORE / IO (Ядро логики)

* **Роль:** Чистая математика и трансформация данных.
* **Ключевые сущности:**
  * **`SignalQueue` (v2.0 Priority Scheduler):**
    * Реализует паттерн **Trampoline**.
    * **НОВОЕ:** Поддержка приоритетов (`enum Priority`).
      * `CRITICAL`: Ввод пользователя, системные события.
      * `NORMAL`: Основная логика вычислений (по умолчанию).
      * `BACKGROUND`: Визуализация, логирование.
    * **Load Shedding:** Метод `isOverloaded()` для реализации "ленивых" вычислений.
  * **`Contact`:**
    * *Link/Unlink API:* Единый механизм создания физических связей. Используется как для сборки, так и для редактора.
    * *Owner Reference:* Прямая ссылка на владельца (`Atom`) для оптимизации вызовов.
  * **`Atom`:**
    * *Hybrid Nature:* Реализует `IDisposable` и `Driver`.
    * *Zero-Allocation:* Кеширование входных данных (`_inputCache`).
    * *Active Capability:* Флаг `isActive` для автоматической регистрации в `DriverManager` при создании.
  * **`Assembly`:**
    * *Safety:* Безопасная утилизация внутренних атомов с проверкой типов (`Std.isOfType`) перед кастом.

### Слой 3: EDITOR / ED (Визуализация)

* **Роль:** Инструмент управления графом.
* **Безопасность памяти (Memory Safety):**
  * **`NodeView`:** Реализован метод `dispose()`. Гарантирует отписку от событий `Contact` и удаление слушителей мыши. Устраняет "зомби-объекты" и утечки памяти.
* **Логика связей (Connection Logic):**
  * **`NodeEditor`:** Отказ от анонимных подписок (`subscribe`).
  * Используется `Contact.link()`, что обеспечивает **Single Source of Truth** (связь существует только если она есть в Blueprint и физически в Contacts).

### Слой 4: DEVICE / GO (Интерфейс пользователя)

* **Роль:** Представление данных (HMI).
* **Оптимизация:** Обновление UI вынесено в очередь с приоритетом `BACKGROUND`, предотвращая фризы интерфейса при тяжелых вычислениях в ядре.

## 3. Протокол Вычислений (Computation Protocol v2.1)

1. **Инициатор:** Драйвер или ввод меняет `contact.value`.
2. **Планирование:**`Contact` ставит задачу `_propagate` в `SignalQueue` с приоритетом `NORMAL`.
3. **Диспетчеризация:**`SignalQueue` выполняет задачи строго по приоритетам:
   * Сначала обрабатываются `CRITICAL` (реакция UI).
   * Затем `NORMAL` (логика каскада).
   * В конце `BACKGROUND` (отрисовка изменений).
4. **Каскад:**`_propagate` использует метод `link` для передачи данных следующим контактам.
5. **UI Update:**`NodeView` обновляет текстовые поля через `BACKGROUND` очередь.

## 4. Визуальные стандарты (Visual Standards)

* **Wire Rendering:** Кубическая кривая Безье.
  * Математика: `Control Points` смещаются по X в зависимости от типа порта (Вход/Выход), обеспечивая естественный поток "слева направо".
* **Color Coding:**
  * Ports: Input (`0xFF8800`), Output (`0x00FF88`).
  * Backgrounds: Dark Grey (`0x333344`).
  * Data Text: Green Monospace (`0x00FF00`).
